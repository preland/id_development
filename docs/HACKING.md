# Changing the language

> **Status: describes current practice.** The loop and the gates named here
> are the ones `idc/tests/run.sh` actually runs.

**Language features are built in the self-hosted compiler**
(`idc/compiler/lex` + `idc/compiler/parse`). There is no other compiler: the Python one, `idc.py`, is deleted.

This document exists because the opposite kept happening, to several people
and several models, and the reason turned out to be mechanical rather than a
matter of preference.

## The bias, and why it is not your fault

It used to cost six times more to change the compiler than to change
`idc.py` (since deleted), and that was the whole explanation.

Changing `idc.py` needed one grep: `grep -n "def parse_function" -A 40`.
Finding the same code here took **six** steps when it was measured —
`parse_program` → `func1.id` → `parse_top` → `p1.id` → `parse_decl_top` →
`f2.id`. The tree was nine directories deep and **212 of its 258 filenames**
(`a1.id`, `gen11b.id`, `t7.id`, `cs2`) said nothing about what was in them, so
the only way to find anything was to already know a symbol to grep for.

Anyone optimising for effort — human or model — takes the one-step path. That
is not a discipline problem, so it did not get a discipline fix:

- **Every file was renamed.** 0 of 258 filenames are now meaningless. The
  same lookup is `front/parse/decl/top/decl/decl_top.id` — the path *is* the
  answer. Directories are named after the stage of work: `front/{tokens,
  tree,parse}`, `mid/{names,types,unique}`, `back/{drive,emit,out}`.
- **Two indexes**, below, for when the path is not enough.

Byte-parity held through all 258 renames, which is the only reason a change
that large was safe to make at all.

The indexes answer different questions:

- **You know the name.** [`MAP.md`](../idc/compiler/parse/MAP.md) — all 737
  functions, each with its file and a one-line purpose. Generated by
  `idc/tools/mapgen.sh`; `idc/tests/run.sh` fails if it is stale. `grep ty_find MAP.md`
  gives the exact path.
- **You know the concept, not the name.** The table in this file. Grepping
  MAP.md for "action limit" finds a function whose comment merely *mentions*
  the limit, not the check that enforces it — that is what the table below is
  for, and it was measured failing before it existed.

## The bootstrap rule, stated exactly

**Stage 0 is `idc/bootstrap/idlex.c` and `idc/bootstrap/idparse.c`**: the C
the compiler emits about itself, checked in. `idc/bin/idc` compiles them with
`cc`, then rebuilds both stages from the working tree through them. `idc.py`
is not part of the bootstrap and is never run by the driver.

That means stage 0 has to understand a new construct **only once the
compiler's own source uses that construct** — and it moves forward in exactly
one commit: the one that teaches the compiler the construct, regenerated with
`idc/tools/regen_bootstrap.sh`. Use the construct in the compiler's own source
in a later commit, once stage 0 can read it. `regen_bootstrap.sh --check` fails
the suite when stage 0 is not what the tree emits.

`idc.py` is gone, so there is nothing else a new construct has to be taught to.
`--target wasm` is implemented by `idc/bin/idc` itself (the C target's C
recompiled for wasm32-wasi), and `idc/tests/conform.sh`'s wasm lane and
`idc/tests/wasm.sh` run it.

`front/` and `mid/` **must not emit C**. That is currently true — verified —
and it is what makes a second target possible. If a change wants to put a C
spelling in `mid/`, the change is in the wrong place.

## Adding a type, worked

The shortest real example, and the shape most changes take:

1. `mid/types/registry/table/rows.id` — one `ty_row(name, kind, width, signed)` call.
2. `back/.../type_column.id` — one `push((import tyc), "<C spelling>")`, **in the
   same position**, because the spelling column is indexed by the registry's
   row number.
3. `idc/tests/conform/` — a case, so every target is held to the same behaviour.

There is no second compiler to change.

## The loop

```sh
idc/bin/idc idc/compiler/parse --check --allow-untested  # the rules only, before a full build
idc/tools/regen_bootstrap.sh --check                  # ok: the compiler's own C unchanged
idc/tools/devshell.sh 'idc/tests/invalid.sh'           # diagnostics, bin/idc
idc/tools/devshell.sh 'idc/tests/conform.sh'           # behaviour, every target
idc/tools/devshell.sh 'idc/tests/run.sh'               # everything
```

`regen_bootstrap.sh --check` is the cheap one and catches most mistakes: it
emits the compiler's own C through `idc/bin/idc` and compares it with
`idc/bootstrap/*.c`, so if you did not mean to change emitted C, it must still
say ok. When you *do* mean to change it, see `idc/bootstrap/README.md`.

There is no differential check against another compiler: `idc.py` is deleted,
and a change to emitted C means only that `regen_bootstrap.sh --check` and the
conformance suite must still agree.

## Writing `id` inside the rule of 3

The friction that used to make people give up and edit `idc.py` instead:

- **A block may perform 3 actions.** Adding a call to an existing function
  often means finding one with a free slot, or splitting it. Look for a
  function that already does 2 things before inventing a new one.
- **A name has one type per compilation unit**, and this tree is one unit.
  `int r`, `string s`, `int i`, `int[] pos` are the established vocabulary;
  reusing them costs nothing and inventing a synonym may collide.
- **Two functions may not share a signature and a body** up to renaming. If a
  new helper is rejected as a duplicate, the one it duplicates is the one to
  call.
- **Never name a file `conf.id`.** That name is the dependency manifest, and
  only a *root's* is read. One anywhere else is neither compiled nor read as a
  manifest, so everything it defines silently ceases to exist — and the only
  symptom is `no such function` at the caller, blaming a file that is fine.
  The compiler now rejects it by name; before it did, it cost a rename
  half an hour of looking in the wrong place.
